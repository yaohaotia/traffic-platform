# 交通线索智能审核与激励平台：项目重构计划书

制定日期：2026-11-03。状态与证据见同目录 `重构执行记录.md`；本文件规定范围、顺序和门槛，不将规划项计为已实现。

验收更新：2026-11-04完成P0—P8。最终证据为`test-reports/P8-final-summary.json`；完整技术栈、运行手册和简历段落均已交付。下文保留立项时的阶段要求，实际调整和验证过程见执行记录。

## 1. 目标与实施方式

围绕园区/校园交通线索，完成“专项征集 → 提交线索 → 合成风险筛查 → 人工审核/复核 → 奖励 → 通知与追踪”。保留独立 Python 模型服务；AI 只输出风险，不直接扣分或判定违章。

原 `server（后端）` 包含尚未提交的用户改动，原前端和模型也有现有成果。采用并行迁移：新后端位于 `car/traffic-platform`，旧系统继续作为行为参考；使用独立数据库，不对原数据库执行清表、覆盖或自动迁移。每个已迁移接口记录差异；切换前完成前端及数据迁移验收。

先做模块化单体，按 identity、campaign、report、detection、review、reward、notification 分包；HTTP/MQ/调度为入口，application 编排事务，domain 定义规则，infrastructure 实现持久化与外部调用。包的职责先落实，再按需要拆 Maven 模块；不为了目录数量强行制造空模块。

## 2. 技术选择与约束

| 部分 | 目标 | 解决的问题 |
| --- | --- | --- |
| 运行基础 | Java 21、Spring Boot 4.x（依赖可获取且兼容后锁定补丁版本） | 新骨架与维护升级 |
| 数据 | MyBatis-Plus Boot 4 starter、MySQL 8、Flyway、HikariCP | 数据迁移、事务、分页、约束 |
| 安全 | Spring Security、BCrypt、JWT、Redis 会话/刷新令牌 | RBAC、资源归属、注销与停用 |
| 异步 | Spring AMQP、RabbitMQ、Outbox/消费记录 | 可恢复的检测、奖励与通知 |
| 缓存和协调 | Spring Data Redis；有明确场景后引入 Redisson | 会话、限流、缓存、后台协调 |
| 调度 | XXL-JOB | 补投、任务回收、超时审核转派、对账 |
| 文件与模型 | 对象存储适配器、Python Flask/PyTorch | 可替换存储、推理契约、风险留痕 |
| 工程 | OpenAPI、Actuator/Micrometer、Docker Compose、Nginx | 文档、健康检查、部署与监控 |
| 测试 | JUnit、Spring Security Test、真实 MySQL/Redis/RabbitMQ 集成测试 | 证明授权、并发和恢复语义 |

JWT 密钥、数据库密码等通过环境注入。开发示例配置与正式配置分离。MySQL 是资金、预算和业务状态的真相源；Redis 锁不替代唯一键和条件更新。MQ 按至少一次投递设计；Confirm 不等于消费者已完成。

## 3. 阶段关卡

执行规则：当前阶段实现完毕，运行指定测试并记录命令、结果、报告位置；只有全部必需检查通过才开始下一阶段。失败、跳过、依赖不可用都不算通过。排查与环境准备可以进行，禁止提前实现未解锁阶段的功能。

单元测试、H2 集成测试、真实服务集成测试分别记录。H2 不证明 MySQL 行锁/SQL 兼容；模拟 Redis/MQ 不证明真实服务正确；模型桩不证明真实权重效果。测试基础设施只用隔离资源，不读写原业务库。

2. 保存现有 8 项 WorkflowTest 的运行结果，不修改原业务代码。
3. 写本计划、执行记录、接口迁移清单，明确模型与支付边界。

交付：计划书、基线报告、迁移清单。

门槛：旧后端编译与 WorkflowTest 全通过；新旧目录/数据库隔离策略确定。环境缺项登记为后续关卡风险，不冒充已具备。

### P1：新工程基础与可启动骨架

步骤：
1. 创建 Java 21 / Boot 4 新项目，锁定依赖；不引入未使用的中间件 starter。
2. 建立健康/版本端点、统一错误响应、参数校验、日志请求 ID。
3. 配置 MySQL 连接与 Flyway；测试 profile 使用独立 H2，正式 profile 禁止默认 H2。
4. 提供 Windows 构建脚本、配置说明、数据库迁移基线。

交付：新项目、启动/测试命令、基础 API。

门槛：`verify` 无跳过且通过；应用上下文启动；健康/版本 API、参数校验、404 和异常响应测试通过；Flyway 在独立 H2 上迁移并验证；打包成功。真实 MySQL 验证列入 P2 门槛。

### P2：身份认证与真实基础设施

步骤：
1. 定义用户、角色、权限、区域关系；BCrypt 存储密码。
2. 实现登录、当前用户、刷新、注销、停用检查，使用 Spring Security 原生 JWT 校验。
3. Redis 存储会话和刷新令牌哈希；原子轮换，限制有效期；短期访问 JWT 每次验证会话存在性，实现注销后失效。
4. 服务端生成身份和权限；禁止注册时自选管理员角色。权限在服务层校验，数据归属在查询/写入中校验。
5. 编写隔离 Docker Compose（MySQL、Redis、RabbitMQ），为真实集成测试准备环境。旧 MD5 用户迁移采用成功验证后重新编码或重置，不直接将旧摘要当新密码。

交付：认证与授权 API、初始化说明、独立测试环境。

门槛：真实 MySQL 建库/Flyway/唯一约束测试；真实 Redis 的 TTL、并发刷新仅一次成功、注销失效、停用失效测试；401/403、伪造/过期 JWT、低权限越权、请求参数校验测试全部通过。不得以 mock/in-memory 替代本关卡。

### P3：征集任务与线索主链路

步骤：
1. 征集任务草稿/发布/关闭、区域、期限、奖励标准与预算配置。
2. 对象存储适配器和图片上传；大小、格式、来源校验，数据库只存对象标识。
3. 线索提交的责任链：身份状态、任务有效性、区域、频率、重复请求；保存奖励规则快照。
4. 线索、检测任务和 Outbox 同事务保存；拆分 detection/review/reward 状态。
5. Idempotency-Key 与请求摘要绑定，同 key 不同内容拒绝；用户列表强制身份过滤。

门槛：真实 MySQL 下重复/并发提交只生成一条线索与事件，回滚不遗留事件；任务过期/关闭、区域越权、图片非法、同 key 不同内容等用例全通过。

### P4：RabbitMQ 可靠检测

步骤：
1. Outbox 投递，处理 publisher confirm、unroutable return、失败重投与投递租约。
2. 消费事件领取 detection_task：短事务领取、事务外推理、携带 attempt/version 条件提交结果。
3. 并发任务领取、超时租约、旧结果拒绝；有限重试、退避、死信和人工重试。
4. 保存模型版本/分数/阈值；疑似合成进入人工复核，不自动扣分。

门槛：真实 RabbitMQ/数据库下重复投递、提交后断连、消费完成未 ACK、失败重启、毒消息、过期结果测试通过；HTTP 推理契约使用桩可重复测试。真实权重联调另记 P8，不用契约测试冒充模型精度验证。

### P5：审核工单与复核

步骤：
1. 按区域与审核能力分配/领取，乐观版本控制防重复处理。
2. 审核通过/驳回/复核；留存操作人、原因、版本与审计日志。
3. 超时转派、旧审核提交拒绝；申诉在奖励结算前完成，已结算更正通过补偿流程处理，不删除原流水。

门槛：多审核员并发领取、跨区域/跨用户越权、重复审核、超时后旧版本写入、复核角色隔离测试通过；消息乱序不改变已经确定的审核版本。

### P6：预算、奖励订单与通知

步骤：
1. 审核确定后，在同一事务预留预算、创建唯一奖励订单并保存事件。
2. 奖励消费者幂等入账：业务关联号唯一，订单/余额/流水同事务；资金使用 BigDecimal。
3. 实现预留、发放、释放三类预算变化，取消/更正使用补偿订单。
4. 站内消息独立订阅审核与奖励事件；模拟提现申请/审批，明确未接真实支付。

门槛：真实 MySQL 并发不超预算、不重复入账、异常回滚完整；重复/乱序消息安全；重复退款只一次；预算与奖励流水对账无差异；失败消息可恢复。

### P7：调度、限流、部署与监控

步骤：
1. XXL-JOB 管理 Outbox 补投、检测回收、审核转派、账务对账。
2. Redis 限流，配置缓存失效；Redisson 只用于明确的跨实例任务协调，数据库幂等继续保留。
3. 配置健康/就绪、业务指标、日志请求 ID、失败告警；Docker Compose 与 Nginx 部署。
4. 实现依赖故障时的可解释行为，禁止静默切到内存会话或丢弃消息。

门槛：双实例重复调度不产生重复业务效果；依赖停止/恢复、配置缺失、重启恢复测试通过；部署启动冒烟与健康/就绪区分正确。性能报告注明机器、样本与持续时间，不虚构 QPS。

### P8：前端切换、模型联调与最终验收

步骤：
1. 改造原 Vue 页面适配新认证、状态、任务/工单/奖励 API，补齐必要页面。
2. 使用固定解释器 `/d/soft/Anaconda/python` 运行 Python；真实权重检测样例，核对标签方向、预处理和超时。
3. 提供只读导出/显式导入的数据迁移工具，映射旧状态与用户；先预演并核对数量，不在原库自动写入。
4. 完成端到端演示、使用文档、架构图、测试报告与基于实装能力的简历描述。

门槛：前端构建；用户→提交→检测→审核/复核→奖励→通知全链路；失败恢复；旧数据预演核对；所有前序阶段回归通过。最终说明真实支付、边缘部署、自动违章模型、ES/分库分表等尚未实现的范围。

## 4. 不纳入首轮的内容

暂不引入全套 Spring Cloud、Dubbo、Nacos、Seata、分库分表或 ES/Canal。需要复杂全文检索、独立服务部署或实际容量依据时再立项。前端升级 Vue 3 也不作为后端认证/MQ 的前置工作。

## 5. 风险与应对

- 当前 Docker daemon 未连接；真实中间件关卡不能靠 H2/mocks 放行。优先准备隔离环境，无法启动则保持关卡未通过。
- Boot 4 和 Jakarta/JSON/测试 starter API 存在升级差异；新骨架验证后再迁移功能。不能因为 Maven 缓存只有旧版本就默默降级。
- 模型解释器缺 torch/torchvision，真实权重验证属于明确门槛；先做模型协议测试，但两者分别标注。
- 原角色 ID=4 与角色名称、菜单权限可能不一致，迁移使用显式角色码与映射，不延续魔法数字。
- 以可复现的代码和测试作为简历依据，计划中的组件不列为已完成。
