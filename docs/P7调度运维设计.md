# P7 调度、缓存与运维设计

制定日期：2026-11-04；P6完整关卡通过后才能开始生产实现。

1. 固定XXL-JOB 3.4.2、Redisson 4.8.0社区版，使用官方发行标签代码核对API，禁止将big-market旧Boot2 starter直接复制进Boot4工程。Redisson只协调有界维护批次，MySQL版本/唯一键继续保证业务幂等。
2. 将Outbox补投、检测回收、审核回收、奖励/通知恢复、游标账务对账接入独立XXL-JOB Handler。开发可选本地调度，但同一实例只运行一种驱动；生产显式配置调度中心地址和非默认accessToken。
3. 跨实例任务用看门狗锁协调；异常必须让调度结果失败并保留日志/指标。锁失效可能重复执行，因此所有业务入口保持数据库幂等，不能宣称Redis锁提供精确一次执行。
4. 保留P3真实Redis提交限流，新增征集任务详情读缓存：查询后仍强制区域/发布状态授权；发布/关闭后提交完成才失效，TTL限制异常失效后的展示延迟。业务提交、审核和资金判断始终读取加锁的数据库当前记录。
5. 配置liveness与依赖readiness、受权限控制的业务指标和积压/死信/人工处理提示。添加OpenAPI接口文档。配置缺失启动失败，Redis会话或数据库不可用不静默切换内存实现。
6. 提供Docker部署与Nginx同源反向代理。证据存储可使用显式共享卷适配器，所有实例挂载同一卷并保持受控ID读取；开发local适配器仍禁止在prod使用，不宣称已接入云厂商存储。
7. 测试真实Redis下两个独立协调客户端竞争、重复维护无重复业务效果、XXL执行器鉴权/实际触发、缓存提交后失效、Redis停止/恢复与健康探针、部署冒烟。测试全部通过并归档后进入P8。
