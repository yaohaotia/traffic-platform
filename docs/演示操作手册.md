## 一次完整演示

1. 运营登录“专项征集”，配置NORTH区域、起止时间、单条奖励与预算，保存草稿后发布。
2. 用户登录选择征集，填写拍摄时间、地点、说明并上传PNG/JPEG。提交后点击刷新查看检测及审核状态。
3. 初审员登录“审核工作台”领取对应工单，查看证据并填写理由。可以通过/驳回或提交独立复核；疑似合成直接进入专门复核。
4. 复核员登录领取待复核工单，独立查看证据后终审。预算不足会保留工单并提示追加预算，不能误判为无效线索。
5. 用户查看“奖励与提现”。后台通过MQ幂等入账，站内通知记录处理变化；模型分数本身不发奖。
6. 用户提交模拟提现；运营在“运营管理”填写理由审批。申请人不能自己审批，批准只是模拟结算，不连接银行或支付平台。
7. 运营查看预算/积压/五类维护任务。更正奖励保留原流水；已冻结或支出导致余额不足时，记录人工追偿，不虚构退款。

演示库已有浏览器验收生成的数据，可以继续新增征集和线索。旧线索位于“我的线索”下的历史档案；旧审核通过不表示已迁入当前奖励账本。

## 本机服务关闭后的恢复

先启动Docker Desktop，再在traffic-platform目录运行：

```powershell
docker compose -f ./dev/compose.yml up -d --wait
docker compose -f ./deploy/compose.yml --env-file ./deploy/.env up -d --wait --wait-timeout 180
& './tools/start-model.ps1'
```

模型调用固定Anaconda并绑定127.0.0.1:5001；如果该端口已有本项目模型进程，不要重复启动。Docker演示经host.docker.internal访问它。首次新环境的依赖安装与凭据初始化见项目README，已有.env不能重新覆盖。
