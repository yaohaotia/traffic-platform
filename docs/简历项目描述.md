# 简历项目段落

项目名称建议：**交通线索智能审核与激励平台**。

时间：原项目按实际开发经历填写；本次企业化重构为2026年11月，不能把新技术栈描述成早期已经交付。

## 可直接放入简历的精简版

**交通线索智能审核与激励平台** | Java后端 / 全栈开发

**技术栈：** Java21、Spring Boot4、Spring Security、JWT、MyBatis-Plus、MySQL、Redis、RabbitMQ、Redisson、XXL-JOB、Flyway、Docker Compose、Nginx、Vue2、Python/Flask/PyTorch。

- 围绕园区交通线索，完成专项征集、证据上传、合成风险筛查、人工审核/独立复核、奖励入账与站内通知，按业务模块构建可部署的单体系统。
- 基于Spring Security、BCrypt、JWT与Redis实现RBAC、区域及资源归属控制；通过原子刷新轮换与会话版本校验支持注销、停用和权限变更后的凭据失效。
- 使用事务Outbox、RabbitMQ确认投递与消费幂等，构建检测任务租约、有限重试、死信隔离和XXL-JOB补偿；推理在事务外执行，旧版本结果不能覆盖新任务。
- 将审核终审、预算预留和唯一奖励订单置于同一事务，通过钱包不可变流水及补偿单保证并发不超预算、不重复入账；完成真实中间件、模型权重及页面链路验证。

## 面试时需要能够解释

1. 为什么不用“审核通过后直接加余额”：审批与预留必须原子化，消费入账另有唯一业务号及不可变流水。
2. Confirm与ACK分别证明什么，如何处理消息已发但Outbox未更新、消费已提交但未ACK。
3. 为什么推理在事务外，如何用版本/租约拒绝晚到结果。
4. 为什么复核排除既往决议人，为什么预算不足不能当成线索无效。
5. Redis锁失效后如何由MySQL条件更新/唯一键继续保护，为什么旧奖励更正不删除原流水。
6. 演示提现只是模拟，模型只做合成风险筛查，当前共享卷不是云存储；没有将边缘部署、真实支付、压测QPS或检测准确率作为本次实装成果。

完整技术栈与架构见同目录`架构与技术栈.md`，最终测试证据见`test-reports`和`重构执行记录.md`。
